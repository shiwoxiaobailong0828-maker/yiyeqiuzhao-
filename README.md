## 为什么是它

秋招的本质是一场**几十条并行流水线**的项目管理：每笔投递都有自己的阶段、日期、截止线和跟进动作。市面上能用的方案是 Excel 和在线表格——但它们没有阶段、没有提醒、没有时间线，更没有隐私可言。

这个作品用**一个 HTML 文件**解决这件事。不用注册、不用联网、不用部署，双击就能跑。

## 30 秒体验路径

1. 点顶栏「**更多操作 → 载入示例数据**」，10 秒看懂全部字段
2. 切到「**投递进度**」，看漏斗图、占比环图和七阶段管道如何自动生成
3. 随便改一笔投递的阶段，回到时间线看事件自动落账
4. 点「**导出备份**」拿到 JSON，再「导入恢复」—— 数据主权完全在你手里
5. 「清空重置」回到干净模板，开始录入你自己的秋招

### AI 助手使用说明

- **用途**：把一段自然语言（面试经历、Offer 待遇、投递安排）发给 AI，它用 function calling 理解意图并结构化，自动填入投递记录 / 面试记录 / Offer 待遇 / 目标岗位 / 待办 / 个人档案。
- **配置**：顶栏「AI 助手」→「设置」，选厂商、填 API Key 和模型名。Key 仅存本机 localStorage。
- **安全**：所有写入先弹预览，用户勾选「确认写入」才落盘，AI 理解错不会误写。
- **CORS 注意**：DeepSeek、通义、智谱、Moonshot 等国产模型浏览器可直连；OpenAI 官方不支持浏览器直连，需用「自定义」填中转地址。

## 为什么是单文件：架构自述

这不是「没做工程化」，是一个刻意的取舍。

求职工具的普适性障碍从来不是功能，而是**启动成本**：需要注册、需要服务器、需要数据库的工具，对"只想今晚把三笔投递记下来"的学生是劝退的。单文件意味着：

- **零信任成本**：数据存本机，想看源码直接浏览器查看，没有黑盒
- **零维护成本**：用户自己就是服务器，作者下线作品也不会坏
- **零分发成本**：文件扔群里、发邮件、存 U 盘，任何一个人双击就能用

代价是放弃了多用户协作和账号体系——对个人求职场景，这个交换是划算的。云端同步留了一个"进阶出口"：想跨设备的人自配一个 30 行的云函数接口即可，不想配置的人永远不需要知道它的存在。

## 数据安全说明

- 所有数据仅保存在当前浏览器的 localStorage
- 「云端同步」默认关闭，需使用者自行填入自己的服务端地址与令牌才会启用
- 简历附件以 Base64 存入本机，云同步时自动剥离正文只传引用
- 「清空重置」需两次确认，且建议先导出备份

### 副本同步规则（一句话版）

**只有一个事实源**：`一页秋招.html`。所有改动只改它，然后**单向覆盖拷贝**到发布版：

| 文件 | 角色 | 能不能直接改 |
|---|---|---|
| `一页秋招.html` | 事实源（唯一进 Git 的 HTML） | ✅ 唯一编辑入口 |
| `deploy-qiuzhao/index.html` | 发布版副本（不进 Git） | ❌ 禁止，只能从事实源拷贝 |

同步后必须校验两处字节一致：

```bash
md5sum 一页秋招.html deploy-qiuzhao/index.html
```

### 发布 SOP

1. 改事实源 → 2. 跑冒烟清单 → 3. 同步发布版（覆盖拷贝）→ 4. `md5sum` 校验一致 → 5. 部署 `deploy-qiuzhao/index.html` 到线上 → 6. 线上功能抽查 + 确认无个人信息/密钥残留。
